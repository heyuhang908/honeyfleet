# honeyfleet 性能与资源实测文案

> 一句话：**"轻量"不是口号，是测出来的。** 全部数字来自真实安装、真实运行、真实测量——不估算、不编造。

---

## ① 首页横幅版（3 个数字 + 1 行结论）

```
≈16 MB   部署体积（含蜜罐二进制 + fail2ban）
≈70 MB   RSS / ≈60 MB PSS 空闲常驻开销（含蜜罐 + fail2ban）
512 MB   VPS 即可完整运行单节点（Debian 12 / 1 vCPU）
```

> honeyfleet 真正的成本不在自己的代码（176 KB），而在防御本身（fail2ban）。我们把每一分内存都花在"该花的地方"，其余全部按需启动、用完即走。

---

## ② 完整版（README「Performance & Reliability」章节可直接用）

### 部署体积：比一张照片还小

| 组成 | 实测大小 |
|---|---|
| honeyfleet 全部代码（8 模块 + 公共库 + 校验闸门 + 工具） | **175.8 KB** |
| sshesame 蜜罐二进制（官方 v0.0.39，SHA256 锁版） | 12.5 MB |
| fail2ban（包 + 配置） | ~3 MB |
| **单节点部署总磁盘** | **≈ 15–16 MB** |

代码只有 176 KB，却能调度 8 个防御模块、跑三层封禁、做完整性监控与联邦推送——因为它是"调度器 + 契约"，真正的重活交给系统自带的 fail2ban/sshd/iptables。

### 运行时内存：花在防御上的每一分都看得见

**真实运行测量**（官方二进制/apt 包，进程稳定后快照）：

| 常驻组件 | RSS | PSS | 说明 |
|---|---|---|---|
| fail2ban-server | 60.5 MB | 51.5 MB | 5 线程；三层 jail 的决策引擎 |
| sshesame 蜜罐 | 9.9 MB | 8.5 MB | 6 线程；Go 单二进制，扛全网扫描 |
| systemd 定时器 | ~0 | ~0 | 无驻留进程，到点才跑 |
| honeyfleet 脚本 | 瞬时 <10 MB | — | 一次性执行，跑完即退 |

**空闲常驻总开销 ≈ RSS 70 MB / PSS 60 MB**，其中 fail2ban 占 ~85%。

**为什么这么轻：**
- **零驻留脚本**：honeyfleet 本体是 Bash + systemd 定时器——不运行时不占内存，定时器本身几乎为 0；
- **Go 单二进制蜜罐**：sshesame 一个文件干完诱捕、记录、日志，不需要语言运行时；
- **复用系统组件**：封禁交给 fail2ban、网络交给 iptables——不重复造轮子，也就不重复吃内存。

### VPS 适配评估

| VPS | 结论 |
|---|---|
| 256 MB | ❌ 不推荐——防御开销已占 25%+，容易进 swap、探针被 OOM 拖垮 |
| **512 MB / 1 vCPU** | ✅ **单节点最低推荐**（蜜罐 + 全模块 + fail2ban 三层） |
| **1 GB / 1 vCPU** | ✅ **推荐甜点**——还能承担 central 角色 + 多 agent 快照 + 面板 |
| 2 GB+ | ✅ 无压力——可跑 central + 多节点 + 附加业务 |

**最低环境建议**：Debian 12 / **512 MB RAM / 1 vCPU**，即可运行完整单节点 honeyfleet。

## ③ 诚实声明（必须保留）

- 测量环境：Ubuntu 24.04（WSL），sshesame 为官方 release 二进制、fail2ban 为发行版 apt 包，均真实安装运行；
- 上述为**进程稳定后的快照值**，非 30 天均值/峰值——持续曲线由 `bench/collector.sh` 上线后产出；
- fail2ban 的 RSS 在真实低配 VPS 上可能略低（本环境加载的 jail/regex 较多），量级一致；
- 未计入业务侧开销（Web/Caddy/监控面板等）——那是你的业务，不是 honeyfleet。
